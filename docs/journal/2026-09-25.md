## 🚧 Challenges & Solutions

### 1. Plaintext Secret Leakage in `UserDefaults`
- **Problem**: `KeychainService` mirrored API keys and VPC tokens to `UserDefaults.standard` under `ai.typesafe.secure.storage.*` to retain state during unsigned simulator runs. This wrote credentials into unencrypted `.plist` sandbox files that persist in unencrypted backups.
- **Solution**: Removed all `UserDefaults` credential writes. Enforced hardware-backed storage via Apple's Security framework with `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`. Implemented an automatic migration routine on startup that transfers legacy secrets into the Keychain and erases them from `UserDefaults`.

### 2. `#filePath` Sandbox Leaks & Runtime Traversal
- **Problem**: `BackendConfigurationStore.loadKeyFromDotEnv` resolved `#filePath` at runtime and crawled directory hierarchies to find `.env` files. This baked developer workstation paths into Release binaries and triggered sandbox security violations on iOS/macOS.
- **Solution**: Removed `#filePath` and bundle-level upward directory traversal entirely. Credentials in production now flow through user settings in Keychain; in tests/CI, credentials flow strictly via `ProcessInfo.processInfo.environment`, failing fast and visibly when required variables are absent.

### 3. Deceptive Mock Fallback Masking Core ML Load Failures
- **Problem**: When `LayaCoreMLEngine` encountered missing or corrupt weights, it trapped the failure and silently substituted a mock predictor closure returning `[0.85, 0.15]`. The UI presented misleading "92% Certainty / AUTO EXECUTED" indicators despite running zero actual on-device inference.
- **Solution**: Completely removed the mock fallback from production code. Replaced it with typed `BackendUnreachableError` propagation containing actionable recovery guidance directing users to Settings.

### 4. Raw PyTorch `.safetensors` Handled as `.mlmodelc`
- **Problem**: Model download and local import allowed `.safetensors` files to be renamed and loaded as `.mlmodelc` bundles, causing `MLModel(contentsOf:)` to fail and triggering the silent mock fallback.
- **Solution**: Implemented strict Core ML bundle format validation in `CoreMLModelManager`. `.safetensors` and `.bin` files are now rejected immediately with typed `CoreMLError.unsupportedFormat` errors explaining that compiled `.mlmodelc` or `.mlpackage` bundles are required.

### 5. Inverted Urgency Rubric Contradicting Canonical Schema
- **Problem**: `MailDetailView.triageBanner` inverted urgency score values: score `3` was displayed as "P0 Critical" and score `0` was displayed as "P3 Low", directly contradicting `EmailTriageDecision.swift` and displaying contradictory urgency labels on the same screen.
- **Solution**: Centralized urgency definitions in `UrgencyPriority` enum with canonical mapping (`0` = P0, `1` = P1, `2` = P2, `3` = P3) and single-sourced priority presentation across all UI views.

## 📌 Key Decisions

### 1. Strict Hardware Keychain Storage with Automated Legacy Purge (SEC-1)
- **Context**: Sensitive credentials had an unencrypted fallback path into `UserDefaults`.
- **Decision**: Persist all authentication tokens exclusively in the Apple Security Keychain (`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`). Detect legacy `ai.typesafe.secure.storage.*` entries in `UserDefaults` during startup, migrate them to Keychain, and purge them immediately from disk.
- **Alternatives Considered**: Encrypting values before writing to `UserDefaults` (rejected: introduces unnecessary key management complexity when the system Keychain is purpose-built for this).

### 2. Environment Precedence & Explicit Test Failure (SEC-2)
- **Context**: Runtime `.env` directory crawling via `#filePath` leaked host paths and risked sandbox violations.
- **Decision**: Eliminate `#filePath` and runtime directory traversal from application code. Prioritize `ProcessInfo.processInfo.environment`, followed by Keychain. In integration tests requiring credentials, fail the test explicitly with clear diagnostic messages if keys are absent, rather than falling back to mocks or disk crawling. Provide a checked-in `.env.example` template and enforce `.env` in `.gitignore`.
- **Alternatives Considered**: Embedding fallback mock API keys into test binaries (rejected: risks credential leakage and conceals authentication regressions).

### 3. Toolbar Triage Interaction Model & PRD Alignment (PRD-1)
- **Context**: PRD-2026-09-25 originally specified an unanchored floating bottom action bar, while implementation elevated triage into the main navigation toolbar (sparkles button in `MailDetailView` and "Triage All" in `MailListView`).
- **Decision**: Maintain the toolbar-based triage interaction paradigm, which honors native Apple Mail UX and preserves reading viewport space. Synchronize PRD documentation (`docs/prd/PRD-2026-09-25-mail-triage-system-one-engine.md`) rather than changing UI code to force an intrusive bottom bar.
- **Alternatives Considered**: Forcing a persistent floating bar over the message content (rejected: degrades message readability and contradicts modern Apple Human Interface Guidelines).

### 4. Zero Tolerance for Silent Mock Fallbacks (SIM-1, SIM-2, IMP-2)
- **Context**: Operational failures in on-device Core ML were caught and masked with synthetic predictions.
- **Decision**: Enforce complete inference authenticity. If weights are missing, corrupt, or unsupported (such as `.safetensors`), fail fast with typed `BackendUnreachableError` and `CoreMLError` providing clear user-facing recovery suggestions. Mock backends are restricted strictly to automated test suites.
- **Alternatives Considered**: Silently redirecting to cloud Jev backend upon Core ML failure (rejected: on-device evaluation must maintain operational honesty; transparent failure is required for reliable offline deployment).
